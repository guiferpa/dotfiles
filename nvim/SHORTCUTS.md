# Neovim shortcuts

Every mapping this configuration defines, plus the plugin defaults worth
knowing. Generated by reading `nvim/lua/`, not from memory — if a key is not
here, it is either a Vim builtin or a plugin default this repo never touches.

**The leader is `,`** (`lua/options.lua:17`, `mapleader` and `maplocalleader`).
Keys below are written literally, so `,ff` means comma then `f` then `f`.

## opencode

The agent (`lua/plugins/opencode.lua`) runs as a separate process and Neovim
talks to it over HTTP. Nothing here works until an `opencode --port` is
running — the plugin starts one in a vertical split on the right the first time
you use a mapping, unless it finds one already up.

Everything lives under `,a`, for *agent*.

| Key   | Mode | Does                                              |
| ----- | ---- | ------------------------------------------------- |
| `,aa` | n, x | Ask about the cursor position, or the selection   |
| `,ab` | n    | Ask about the whole buffer                        |
| `,ad` | n, x | Ask about the diagnostics in range                |
| `,as` | n, x | Open the picker: prompts, commands, servers       |
| `,ao` | n, x | Operator — append a motion's range to a prompt    |
| `,an` | n    | New session                                       |
| `,ax` | n    | Interrupt whatever the agent is doing             |
| `,au` | n    | Scroll the agent's output up half a page          |
| `,ae` | n    | Scroll the agent's output down half a page        |

### How to actually use it

`,as` is the one to learn first. It lists everything the plugin can do —
built-in prompts (`explain`, `fix`, `review`, `test`, `optimize`, `document`,
`implement`, `diagnostics`), session commands, and server connections. The
other mappings are shortcuts to things reachable from there.

`,aa` is the free-form path. It opens an input pre-filled with `@this: `, so
whatever you type is asked *about the code under the cursor* — or about the
visual selection, if you have one. Press `<Up>` in that input to browse recent
asks, and `<Tab>` to complete context placeholders and subagent names.

`,ao` is an operator, which is the part that pays off once it clicks. It takes
a motion, so it composes the way `d` and `y` do:

```
,aoap     append the current paragraph to a prompt
,aoi{     append the contents of the block
,ao3j     append the next three lines
,aoo      append the current line (doubling the operator, as with dd)
```

Placeholders you can type in any prompt, each replaced with real context:

| Placeholder    | Expands to                                             |
| -------------- | ------------------------------------------------------ |
| `@this`        | The range or selection, else the cursor position       |
| `@buffer`      | The current buffer                                     |
| `@buffers`     | Every open buffer                                      |
| `@diagnostics` | Diagnostics in the range, else in the buffer           |
| `@marks`       | Global marks                                           |
| `@quickfix`    | The quickfix list                                      |
| `@visible`     | The text currently on screen                           |

**Save before you ask.** opencode reads referenced files from disk, so unsaved
changes are invisible to it.

### When the agent wants to edit a file

It asks first. The proposed change opens in a new tab as a native Vim diff,
and these keys apply *inside that diff*:

| Key     | Does                                                          |
| ------- | -------------------------------------------------------------- |
| `da`    | Accept the whole edit                                          |
| `dr`    | Reject the whole edit                                          |
| `]c`    | Next change                                                    |
| `[c`    | Previous change                                                |
| `dp`    | Accept only the hunk under the cursor, reject the rest         |
| `do`    | Reject only the hunk under the cursor, reject the rest         |
| `q`     | Close the diff                                                 |

`dp` and `do` are Vim's own diff-put and diff-obtain — the plugin leans on them
rather than inventing its own.

Files the agent edits are reloaded in the buffer automatically; the plugin
turns on `autoread` for exactly this.

Run `:checkhealth opencode` if something is not connecting.

Defaults from oil, listed because the buffer is a normal editable buffer and
the keys are not obvious. `g?` shows this same list in Neovim.

| `-`     | Go to the parent directory               |
| `_`     | Go to the current working directory      |
| `<C-s>` | Open in a vertical split                 |
| `<C-h>` | Open in a horizontal split               |

| `<C-p>` | Preview without leaving the list         |
| `<C-l>` | Refresh                                  |
| `<C-c>` | Close                                    |
| `` ` `` | `:cd` into the directory                 |

Edits to an oil buffer are edits to the filesystem: delete a line to delete a
file, change a name to rename it, then `:w`. This config sets
`skip_confirm_for_simple_edits`, so simple ones apply without a prompt.

## Editing

| Key  | Mode | Does                            | Where               |
| ---- | ---- | ------------------------------- | ------------------- |
| `ff` | n    | Format the buffer (conform)     | `plugins/format.lua` |
| `ll` | n    | Lint the file now (nvim-lint)   | `plugins/lint.lua`  |
| `,c` | n    | Clear the search highlight      | `lua/keymaps.lua`   |

Linting also runs on its own at `BufWritePost` and `BufReadPost`, so `ll` is
only for forcing it in between. The mapping does not exist on the startup
screen — nvim-lint loads on `BufReadPre`, so `ll` appears once a file is open.

`nvim-surround` is installed with its defaults: `ys` add, `cs` change, `ds`
delete, plus `S` in visual mode.

### Lisp buffers only

`nvim-paredit` defaults, active only in `clojure`, `fennel`, `scheme`, `lisp`
and `janet` buffers.

| Key                | Does                              |
| ------------------ | --------------------------------- |
| `>)` / `<(`        | Slurp forwards / backwards        |
| `<)` / `>(`        | Barf forwards / backwards         |
| `>e` / `<e`        | Drag element right / left         |
| `>f` / `<f`        | Drag form right / left            |
| `>p` / `<p`        | Drag element pair right / left    |
| `,o` / `,O`        | Raise form / element              |
| `,@`               | Splice sexp                       |
| `W` / `E`          | Next element head / tail          |
| `B` / `gE`         | Previous element head / tail      |
| `(` / `)`          | Parent form's head / tail         |
| `af` / `if`        | Around form / in form, as objects |

Two things to note in that table. `,o` collides with the `,oe` that opens oil,
so in a Clojure buffer `,o` waits for `timeoutlen` before raising the form.
And `W`, `E`, `B` replace Vim's WORD motions inside those filetypes.

## Completion

From `plugins/completions.lua`, insert mode, while the menu is open.

| Key         | Does                          |
| ----------- | ----------------------------- |
| `<CR>`      | Accept the selected item      |
| `<C-Space>` | Trigger completion            |
| `<C-e>`     | Abort                         |
| `<C-b>`     | Scroll the docs up            |
| `<C-f>`     | Scroll the docs down          |

Selection uses the `cmp` insert preset, so `<C-n>` and `<C-p>` move through the
list.

## Collisions worth knowing

These are consequences of the mappings above, not bugs to fix blindly — but
they explain surprising behaviour.

- **`gr` hides Neovim 0.11's own LSP prefix.** A stock 0.11.6 ships `grn`
  (rename), `gra` (code action), `grr` (references), `gri` (implementation) and
  `grt` (type definition). Mapping `gr` on its own means none of those can ever
  fire — and `grt` has no replacement here.
- **`rn`, `ff` and `ll` shadow builtin motions.** Vim waits `timeoutlen` on the
  first key of each: `r` before a replace, `f` before a character search, `l`
  before moving right. `r` then `n` no longer replaces a character with `n`,
  and `ff` no longer jumps to the next `f`.
- **`,c` waits before clearing the highlight**, because `,ca` and `,ct` share
  its prefix. It fires after `timeoutlen`, or immediately on any key that
  cannot continue a mapping.
- **The opencode mappings deliberately avoid the plugin's suggested ones.**
  `<C-a>` and `<C-x>` are increment and decrement, `go` is a motion, and the
  suggested `<S-C-u>`/`<S-C-d>` need a terminal that distinguishes Ctrl-Shift
  from plain Ctrl — Rio only does with `use-kitty-keyboard-protocol`, which
  `rio/config.toml` leaves off.
